---
title: Teams
description: Create and manage a user's own teams with the OrganizationsClient, and invite members with a revocable token.
---

A **team** is an organization without a domain. It belongs to the user who created it, who is
its first owner, and it never takes part in organization selection: a team cannot become the
`org_id` of a token. Companies with a domain and auto-enrollment stay an auth-service admin
decision and are not available here.

The calls come from `user.organizations` (`OrganizationsClient`). The decision is always
auth-service's: your code asks and obeys. Operator side: [Organizations](https://docs.circle-cyber.com/auth-service/docs/concepts/organizations)
in the auth-service documentation.

## Prerequisites

- auth-service `0.3.0` or later.
- `teamManagement: true` in `createAuthClient`: it asks for the `organizations:self:manage`
  scope and the auth-service audience at sign-in, so the user must sign in again after the
  option is turned on.
- Teams are enabled for the application. When the `org` claim is on, the application's
  **Teams** switch is on by default and can be turned off independently.
- Scope required by each method:

| Method | Accepted scope |
| --- | --- |
| `list()` | `organizations:self:manage` or `resources:self:manage` |
| `create()`, `join()`, `leave()`, `createInvitationToken()`, `revokeInvitationToken()` | `organizations:self:manage` |

  An application with only `resourceSharing` can therefore read the user's organizations and
  pick one as a resource audience, but cannot create or manage a team.

## Create a team

```ts
import { createAiClient } from "@circle-rd/auth-ai";
import type { AuthClient, GrantManager } from "@circle-rd/auth-ai";

declare const auth: AuthClient;
declare const grants: GrantManager;
declare const grantId: string; // the signed-in user's `sub`

const user = createAiClient({ auth, grants }).forUser(grantId);

const team = await user.organizations.create({
  name: "Acme Lab",
  logo: "https://cdn.example.com/acme-lab.png",
});

console.log(team.id, team.slug, team.role); // owner
```

The slug is derived by auth-service from the name, with a random suffix, so two teams with
the same name never collide. A user may create a bounded number of teams (`TEAM_MAX_PER_USER`,
10 by default); the quota is checked under a lock.

## List, filter and leave

```ts
const all = await user.organizations.list();
const teams = await user.organizations.list({ team: true });
const companies = await user.organizations.list({ team: false });

await user.organizations.leave(team.id);
```

Leaving a company is refused (`ORG_012`), and the last owner of a team cannot leave
(`ORG_011`) until ownership is transferred.

## Invite members

An owner issues one invitation token per team. It is valid for seven days, allows unlimited
joins until it expires or is revoked, and is shown once: only its hash is stored. Issuing a new
token revokes the previous one.

```ts
const invitation = await user.organizations.createInvitationToken(team.id);
// Show `invitation.token` once; it expires at invitation.expiresAt.

// On the invited user's side:
const joined = await user.organizations.join(token);

// Or revoke it before it expires:
await user.organizations.revokeInvitationToken(team.id);
```

Joining an unknown, expired, revoked or company token answers the same `ORG_014`, so a caller
cannot tell them apart. Joining a team one already belongs to is `ORG_005`.

## Methods

| Method | Description |
| --- | --- |
| `list({ team? })` | The user's organizations. `team: true` keeps teams, `false` keeps companies, omitted keeps both. |
| `create({ name, logo? })` | Creates a team owned by the user; `name` is 1 to 100 characters, `logo` an HTTPS URL. |
| `join(token)` | Joins a team with an invitation token, as a plain member. |
| `leave(organizationId)` | Leaves a team. |
| `createInvitationToken(organizationId)` | Issues `{ token, expiresAt }`; returned once. |
| `revokeInvitationToken(organizationId)` | Revokes the team's active invitation token. |

Every input is validated before any request (`CFG_001`). Reserved fields (`domain`, `slug`,
`autoEnrollEnabled`, `team`) are rejected: a team is always domain-less and the slug is derived
server-side.

## Errors

An auth-service refusal is an `API_001` whose `details.apiCode` carries the auth-service
code. The common ones are:

| Code | Status | Cause |
| --- | --- | --- |
| `ORG_003` | 400 | Invalid name or filter. |
| `ORG_001` | 404 | The organization does not exist. |
| `ORG_004` | 404 | The user is not a member of the organization. |
| `ORG_005` | 409 | The user already belongs to the team. |
| `ORG_011` | 409 | The last owner cannot leave the team. |
| `ORG_012` | 403 | The operation is reserved to teams (leave, invitation token). |
| `ORG_013` | 403 | The per-user team quota is reached. |
| `ORG_014` | 404 | The invitation token is unknown, expired or revoked. |
| `AUTH_011` | 403 | The token lacks the organization scope, or the caller is not an owner. |
| `RATE_001` | 429 | The team-write rate limit was reached (create, join, invitation token). |
